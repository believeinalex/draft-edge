# Season Data (2026-27 LePrawn)

The draft is over and the project is now used for in-season management. This directory holds the league's ground-truth data.

| File | Contents |
| --- | --- |
| `draft_2026-10-18.txt` | Official Yahoo draft results from Sunday, Oct 18 2026 (180 picks, 15 teams × 12), in the format `N.<TAB>Player (NBA - POS)<TAB>$X<TAB>Fantasy Team`. |
| `transactions.json` | Every add, drop and trade since the draft, in date order, as entered from Yahoo's transaction log. |
| `league.json` | Generated by `build_season.js`: every pick; each team's **current** roster (draft rosters with transactions applied, each player tagged `acquired: draft/FA/Waiver/trade`), draft spend, and acquisitions used of the 18 allowed; matched `players.js` rank (`rk`) and `projZ`, projected full-season category totals, and projected roto points and rank. |
| (stats) | Season-to-date stats from `stats/latest.json` are attached per player (`stats`), with team `actualTotals`, `actualRoto` and `actualRank`. See `stats/README.md`. |
| `lineups/raw/YYYY-MM-DD.txt` | Verbatim pastes of Yahoo's League > Rosters page: each team's **locked lineup for the current week** (slots, injury tags, games today). Parsed by `parse_lineups.js` (`npm run lineups`) into `lineups/YYYY-MM-DD.json`. |
| `standings/YYYY-MM-DD.json` | Yahoo's real standings (category totals per team and GP), transcribed from the Standings page. The latest is scored into roto points as `realTotals`, `realRoto`, `realRank` and `yahooRank` on each team. This is the ground truth; `actualRoto` is only an estimate from player stats. |
| `history/prior_standings.json` | Final Yahoo standings (category totals + GP) from the two previous seasons: 2025-26 (12 teams; the user finished last after injuries and disengaging, 478 GP) and 2024-25 (13 teams; the user finished 5th). Use as end-of-season benchmarks, comparing per-GP rates rather than raw totals, since league size and GP differ. |
| `injuries/YYYY-MM-DD.json` | Yahoo's public NBA injury report (`npm run injuries`; re-running the same day replaces that day's file). Statuses: O out, D doubtful, Q questionable, P probable. The latest is attached to rostered players as `injury`. |
| `morning_report.js` | `npm run report` (or `npm run morning` to fetch first): writes `reports/YYYY-MM-DD.md` with last night's over/under performers (game z-score minus projected per-game z-score), injury changes and projected standings after tonight (latest Yahoo standings + games since, estimated from player stats + tonight's ESPN schedule × active lineups, weighted by injury status). |
| `build_season.js` | Regenerates `league.json` (`npm run season`). |

## Notes
- **Managed teams:** The user's team is **Shut Up and Jam Gaiden** (`myTeam`, `isMine`). The user also manages **Finn will cook Burt**, their son Finn's team (`managedTeams`, `isManaged`). Default to Shut Up and Jam Gaiden; look at Finn's roster when asked. Both teams are in the same league, so any trade between them should be fair to Finn's team as well.
- **Team renames:** "Cole is like that" was named "Cole's aura tuff team" at draft time (see `TEAM_ALIASES`).
- **Players outside `players.js`** (the 439-player pool since the 2026-10-27 projection refresh; 300 at draft time) have `rk: null` and **count as zero** in projections. No currently rostered player is outside it. This pulls down any team rostering them. For example, Finn's draft-day projection was low partly because Amir Coffey and Kevin Love counted as zero.
- **Projections** are `players.js` per-game stats (source: `utils/projections.csv`, loaded with `node utils/update_projections.js`; last refreshed 2026-10-27) × projected GP, summed over **every** rostered player. A team stashing a 13th player on IL therefore gets their full stats added. Bench usage, actual injuries and the weekly lineup lock are not modeled. Treat this as a rough baseline, not a forecast.
- **This draft is already part of the price data** as `drafts/mock_2026-10-19_00-07-.txt`. Do **not** run it through `utils/analyze_mock.js` again: re-archiving it would double-count it in the empirical prices.
- **Weekly lock:** rosters lock weekly, so moves made mid-week appear in Yahoo's lineup from the following week. `league.json` tracks **ownership**, meaning every logged move applied immediately. The latest lineup snapshot adds `thisWeek` (slot, injury status, game today, or `null` if the player joins next week) to each player, and `pendingIn`/`pendingOut` to each team. The build warns about any ownership/lineup difference that no logged transaction explains.
- **Lineup paste quirks:** if the first team's name is cut off the copy, it is inferred from roster overlap. A team with fewer than 9 listed players is treated as cut off and only partially checked. Abbreviated names ("N. Alexander-Walker") are expanded from that team's roster.

## Recording transactions
1. Append new entries to `transactions.json`, taken from Yahoo's league transaction log. Use `add_drop` for FA/waiver moves (`via: "FA"` or `"Waiver"`) and `trade` with a `to` team per player.
2. Run `npm run season`. If a drop or trade names someone who isn't on that roster, it fails with an error rather than producing a silently wrong roster.
3. Adds count toward the 18-acquisition season limit; trades do not.
